## Global Constraints

- Only focus-timer time is study time. Nothing in v1.2 creates, extends, pauses or deletes focus
  time; existing accounting tests pass unchanged (spec §6, appplan §5).
- Picking a task whose effective subject differs from the timer's sets task and subject as **one**
  session split (one closed row, one new row) on the pomodoro's `pomodoroId` and `dayKey` (spec §3.8).
- The intention is held by the controller (`TimerState.intention`) and written to
  `sessions.intention` on the current focus segment's rows; editing it updates the open row and
  later rows and never splits a row. The outcome `done|partly|not` is stored as `sessions.outcome`
  on every row of that pomodoro, asked only after ≥ 1 min of focus with an intention set (spec §3.11).
- Migration v4 is one migration, with the pre-migration backup; v1–v3 are never edited; `tasks` is
  renamed `tasks_v1_archive`; the new `tasks` id sequence is seeded above the old ids (spec §5).
- Settings defaults, verbatim: `countdownPips: true`, `rollTasksForward: false`,
  `sessionIntention: true`, `revisionTags: ['lecture']`, `revisionDays: [1, 3, 7, 21]` (1–4 values,
  each 1–90); `WidgetId` += `'deadlines'`, closed by default (spec §5).
- Task fields (spec §3.6): title 1–500 chars; note 0–5000, plain text; estimate 5–600 min, picker
  presets 15, 30, 45, 60, 90, 120, 180 + custom; tags 0–8, each `[a-z0-9-]{1,24}`, stored lower-case;
  subtasks 0–30, text 1–200, row shows "2/5"; repeat none, `daily`, `weekdays`, `weekly`, or
  `every N days` (N 2–30), dated tasks only; reminder optional `HH:MM`, dated tasks only; kind
  `task` or `revision`; a task lives on exactly one of a day or a list; new tasks default to today.
  Lists: name 1–60 chars, optional subject link, max 20.
- Limits: 20 lists, 12 popped notes, 6 stats widgets, 8 tags, 30 subtasks; the controls disable at
  the limit with a tooltip; notes use "Up to 12 notes on the screen" (spec §3.2, §7).
- Day keys are study-day keys with the rollover hour: the planner's "today" matches the stats'
  today. Repeat and revision dates are computed on day keys, never ms (spec §3.6, §7).
- Reminders: a Windows notification "Reminder · <title>" at the wall-clock time on the task's study
  day; a time before the rollover hour falls on the next calendar date; fires once per task-day;
  missed while closed: fired at launch if ≤ 60 min late, otherwise dropped; follows the existing
  `notifications` setting; scheduled in main (spec §3.6).
- Deadlines: title 1–120, kind `exam | coursework`, due stored as local wall clock
  `YYYY-MM-DDTHH:MM`, default time 09:00 for exams and 12:00 for coursework; countdown ≥ 48 h
  "23d 4h", < 48 h "31h 12m", < 1 h "42m 08s" (updates every second), past due "Due"; countdowns
  use the wall clock (spec §3.10).
- Stats widgets: up to 6; cards Total time, By subject (top 6 + "Other"), Goal + streak,
  Estimates; ranges Today · Week · Month; "Add stats widget…" adds a Total time · This week card
  (spec §3.12).
- New floating instances (stickies, stats widgets) cascade from `START {0.5, 0.3}` by
  `CASCADE {0.03, 0.04}`, 6 steps (as images) and never auto-hide (spec §3.2, §3.12).
- YouTube `SpaceOpts.quality: 'auto' | '1080' | '1440' | '2160'`, default `'auto'`; targets
  1920×1080, 2560×1440, 3840×2160 device pixels; levels `hd1080`, `hd1440`, `hd2160`; the badge

- Shortcuts added: **B** (board), **V** (background play/pause); Help (`?`) lists them (spec §4).

## Review Focus

1. **The single split.** `timer:setTask` / `timer:startTask` with a subject change must close
   exactly one row and open exactly one, with the same `pomodoroId` and `dayKey` (v1.1 ruling A3).
   Setting subject then task as two splits is the bug to look for. `setIntention` never splits.
2. **Migration v4.** The `tasks` sequence must sit above the archive's ids, its AUTOINCREMENT
   counter and every `sessions.task_id`, or a new task inherits old focus time as its "actual".
   The `stat_widgets` column `range` is quoted (`"range"`). A failing step leaves v3 intact.
3. **The interim legacy widget.** From Task 3 to Task 33 the old Tasks code reads and writes
   `tasks_v1_archive` (from Task 14 through `legacyTasks:*`). After Task 33 nothing writes the
   archive: the reviewer greps `tasks_v1_archive` and `legacyTasks` across `src/` and `e2e/`.
4. **Roll forward** is off by default, moves only open tasks on days before today, keeps the
   first `rolledFrom`, is idempotent, and runs at launch and on the date-watch study-day change.
5. **Reminder time maths**: before-rollover times land on the next calendar date; a DST day
   resolves with local wall time; `reminded_day` makes it once per task-day; `notifications` off
   means nothing shows.
6. **Pips** only for a running segment crossing 3, 2, 1 in consecutive emitted seconds; a jump
   (sleep, hidden window), a pause, Skip or Reset plays none; the tick is replaced, not doubled.
7. **Drag and drop** dropped outside any target moves nothing; every drag has a keyboard
   alternative (the detail popover's placement picker).
8. **"Pause background" label clash.** `SpaceBackground` already has a reduced-motion button with
   the text "Pause background" / "Play background"; tests for the new top-bar button are scoped to
   the top bar (`header`).
9. **Quality sizing** divides device pixels by `devicePixelRatio`, covers the window, stays
   centred; Auto keeps today's sizing unchanged.
10. **Limits** are enforced twice: main rejects (`IpcValidationError`), the UI disables + tooltips.
11. **Same-elapsed comparisons** at period edges (a Monday, the 1st, 31 March vs February) and the
    Today card's live tick.
12. **Wall clock vs study day.** Deadlines and reminders use the wall clock; planner days, repeat,
    revision and stats use study-day keys.

`focusedMs = Σ actual`; `ratio` = focused / planned to 1 dp; `overruns` = the 3 largest
